# 01. Аудит актуального проекта

## Что установлено по коду

Проект использует Next.js `16.3.4`, React `19.2.8`, Three.js `^0.185.1`, R3F `^9.7.0`, Drei `^10.7.8`, Lenis, Zustand и React Three Postprocessing. Версии здесь взяты из `package.json`; фактически установленные версии предстоит проверить после установки зависимостей.

Главная `app/page.tsx` ведёт через имя, полосу стека, манифест, направления, опыт и технологии к работам. `HomeScene.tsx` монтирует восемь сцен. `HeroCore.tsx` создаёт стопку RoundedBox, слайдер и кнопку; объекты реагируют на курсор и скорость скролла. Это уже рабочая интерактивная основа, но её визуальный словарь близок к демонстрации UI-примитивов.

На странице проекта `ProjectWorld.tsx` использует общий приём: модель справа, Float и поворот от глобального прогресса страницы. У проектов есть отдельные настройки и ассеты, однако основная механика показа повторяется.

В `ProjectModel.tsx` процедурные типы сейчас получают один `ProceduralPlaceholder` — икосаэдр. Названия `metaballs` и `kanban` в данных не означают, что соответствующие сцены реализованы.

`CoreMaterial.ts` содержит кастомный shader, но поиск `createCoreMaterial` в `src` обнаружил только определение. Текущий hero этот материал не использует. Поля качества `particleCount`, `dof`, `raymarchOctaves` тоже нельзя считать доказательством готовых эффектов: нужно сверять каждое с реальным потребителем.

## Почему результат может восприниматься слабым

Это выводы из структуры и реализации; без браузерного просмотра нельзя оценить точные ракурсы, контраст или субъективную выразительность текущего кадра.

| Наблюдение | Вероятное следствие | Решение |
| --- | --- | --- |
| Большой блок резюме перед работами | Долго нет доказательства уровня | Вывести selected work сразу после hero |
| Много отдельных сцен для пунктов резюме | Внимание распределяется между слабо связанными объектами | Единая пластика и три подробно поставленных мира |
| Hero из узнаваемых UI-примитивов | Мало собственного силуэта и материальности | Новая авторская геометрия, полноценный lookdev |
| Float и вращение модели как повторяемая механика | Проекты могут ощущаться одинаково | Разные действия: натяжение ткани, разрез керамики, послойная сборка |
| Несколько ярких акцентов, glow, grain, декоративные линии | Эффекты могут конкурировать с формой | Одна базовая палитра, эффекты по конкретному назначению |
| В коде больше названий эффектов, чем реализаций | Техническая амбиция не превращается в изображение | Принимать эффект по записи и замерам |

## Конкретные технические замечания для реализации

- В `CoreMaterial` нормаль после `normalMatrix` находится в view space, а направление взгляда вычисляется в world space. Для повторного использования привести вычисления к одному пространству. Растяжение позиции также должно учитываться в нормалях.
- Там же `smoothstep(0.15, -0.35, ...)` имеет обратный порядок краёв; такой вызов не является надёжным способом инверсии. Использовать корректные края и явное `1.0 - smoothstep(...)`.
- `PostFX` отключает и renderer AA, и composer multisampling. Само наличие composer не гарантирует сглаживания: в показанном наборе нет явного SMAA/FXAA. Проверить тонкие кромки, выбрать и замерить AA.
- На `medium` окружение отключено в текущих сценах. В новой версии сохранить дешёвое статическое освещение отражений: металл без него может потерять характер.
- `reducedMotion` выбирает `medium`, однако показанные `useFrame` продолжают pointer/scroll-анимацию. Профиль качества не заменяет системную настройку движения.
- Все восемь компонентов HomeScene смонтированы вместе. `visible=false` не освобождает ресурсы и само по себе не останавливает callback. Нужен явный жизненный цикл.
- Сжатый GLB на диске не показывает стоимость текстур в GPU. Текущие модели занимают примерно 4–144 KiB каждая по `du`, но их художественное качество и runtime-память этим не подтверждены.

## Недостающие материалы

Для каждого featured-проекта нужны: главный экран desktop/mobile, 2–3 доказательных фрагмента интерфейса, короткая запись взаимодействия, описание личного вклада и источник любых числовых результатов. В `public/projects/` обнаружены preview для Silkworm, realtime-chat и kanban; комплект для Simplex и 3D Outlet нужно подготовить.

Происхождение моделей и права использования проверить по исходным данным; имена файлов не доказывают наличие лицензии. Это производственная задача по конкретным ассетам, а не повод останавливать подготовку дизайна.

## Baseline перед первым изменением кода

Сохранить кадры `/`, `/work`, одного `/work/[id]`, `/resume` на 1440×900 и 390×844, запись полного scroll и список console/network ошибок. После установки зависимостей выполнить существующие lint/typecheck/build и записать исходные сбои отдельно. Эти результаты станут точкой сравнения, а не ограничением новой арт-дирекции.
