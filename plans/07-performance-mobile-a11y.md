# 07 — Производительность, мобилка, доступность, SEO

Этот файл — главный ограничитель. Любая идея из файлов 04 и 05 проверяется здесь
и урезается, если не проходит.

## 1. Бюджеты

| Метрика | Десктоп | Мобилка (Moto G Power класс, 4G) |
| --- | --- | --- |
| LCP | < 1.5 с | < 2.5 с |
| INP | < 150 мс | < 200 мс |
| CLS | < 0.02 | < 0.02 |
| JS до интерактивности (без 3D-чанка) | < 140 KB gz | < 140 KB gz |
| Общий вес 3D-чанка | < 320 KB gz | < 320 KB gz |
| Сумма ассетов до первого 3D-кадра | < 900 KB | < 550 KB |
| Устойчивый FPS | 60 | 45+ |
| Время до первого 3D-кадра | < 2.0 с | < 3.0 с |
| Lighthouse Performance (мобилка) | — | ≥ 85 |

Lighthouse 85+ на мобилке для сайта с WebGL — амбициозно, но достижимо, потому
что 3D грузится после LCP и не блокирует основной поток. Это, кстати, и есть
главный технический аргумент портфолио: **автор умеет делать тяжёлую графику,
не убивая метрики** — ровно то, что написано у него в резюме про Lighthouse.

Бюджеты проверяются в CI (Lighthouse CI + `size-limit`). Превышение — красная
сборка, а не «потом поправим».

## 2. Тиры качества

```ts
type Tier = 'ultra' | 'high' | 'medium' | 'flat'
```

| Параметр | ultra | high | medium | flat |
| --- | --- | --- | --- | --- |
| DPR | до 2.0 | до 1.75 | до 1.25 | — |
| Частиц | 262k | 131k | 65k | 0 (спрайт) |
| Шаг симуляции | каждый кадр | каждый кадр | через кадр | — |
| Transmission | 2 экз., samples 6 | 1 экз., samples 2 | фейк | нет |
| Порталы | все видимые живые | 2 живых | статичные кадры | картинки |
| DOF | да | нет | нет | нет |
| Bloom | mipmap | mipmap | простой | CSS |
| Тени | soft PCF | PCF | запечённые | нет |
| Raymarch-фон | 5 октав, 0.5x res | 3 октавы, 0.5x res | CSS-градиент | CSS-градиент |
| Физика | 20 тел | 20 тел | 12 тел | нет |
| Аудио | да | да | нет | нет |

### 2.1 Определение стартового тира

Не полагаться на один сигнал. Считаем скор:

```ts
function detectTier(): Tier {
  if (!hasWebGL2()) return 'flat'
  if (prefersReducedMotion() && !userOverrode()) return 'medium'
  if (saveData()) return 'flat'

  let score = 0
  score += deviceMemory() >= 8 ? 2 : deviceMemory() >= 4 ? 1 : 0
  score += hardwareConcurrency() >= 8 ? 2 : hardwareConcurrency() >= 4 ? 1 : 0
  score += isMobileUA() ? 0 : 2
  score += gpuTierFromRenderer() // WEBGL_debug_renderer_info, грубая эвристика
  score += hasFloatRenderTargets() ? 1 : -2

  return score >= 7 ? 'ultra' : score >= 4 ? 'high' : score >= 2 ? 'medium' : 'flat'
}
```

Отдельно: **iOS Safari получает потолок `high`** независимо от скора. WebGL там
исторически быстро упирается в лимиты памяти и убивает контекст, а восстановление
контекста на живом сайте выглядит как краш.

### 2.2 Автопонижение в рантайме

```tsx
<PerformanceMonitor
  bounds={() => [45, 58]}
  flipflops={3}
  onDecline={() => quality.downgrade()}
  onFallback={() => quality.set('flat')}
/>
```

Правила:
- понижение только вниз, автоповышения нет (иначе сайт «пульсирует» качеством);
- между понижениями пауза 3 с;
- 3 срабатывания подряд → `flat` и одноразовый ненавязчивый тост
  «Включён облегчённый режим» с кнопкой «Вернуть эффекты»;
- выбор пользователя запоминается в `localStorage` на 30 дней.

### 2.3 Ручной переключатель

В HUD — иконка качества с четырьмя положениями. Это не костыль, а фича: технический
читатель оценит, что автор дал контроль, а не решил за него.

## 3. Мобильная версия

Мобилка проектируется отдельно, а не «сжимается» из десктопа.

### 3.1 Что меняется структурно

| Секция | Десктоп | Мобилка |
| --- | --- | --- |
| Hero | текст слева, ядро справа | текст сверху, ядро снизу 45vh |
| Фокус | круговая орбита | вертикальная карусель со snap |
| Опыт | горизонтальный коридор | вертикальная шахта |
| Скиллы | сосуд + бросок мышью | сосуд + гироскоп + кнопка «встряхнуть» |
| Витрина | горизонтальная лента порталов | вертикальный snap-стек, живой портал один |
| Кейс проекта | 3D слева, текст справа | 3D-«окно» между текстовыми блоками |
| Курсор-линза | есть | нет, вместо неё «капля» на тапе |

### 3.2 Мобильные правила

- **Все тап-таргеты ≥ 48 px**, включая элементы, которые «кликаются» в 3D.
  Для 3D-объектов расширяем зону невидимым коллайдером.
- **3D не перекрывает текст.** WebGL-слой на мобилке всегда либо за текстом с
  затемнением, либо в отдельном блоке-«окне», но не поверх абзаца.
- **Ничего важного в нижних 15% экрана** — там панель браузера и большой палец.
- **Учитывать `100dvh`, а не `100vh`** — иначе на iOS скачет вьюпорт при скролле.
- **Отключить `overscroll-behavior`** на контейнерах со snap.
- **Тач-события через `pointer-events`**, не отдельная ветка кода. R3F даёт это
  из коробки при `eventPrefix="client"`.
- **Тестировать на реальном устройстве**, минимум: iPhone среднего возраста и
  Android на Snapdragon 6-й серии. Chrome DevTools throttling врёт про GPU.

### 3.3 Термальный троттлинг

На телефоне через 2–3 минуты непрерывного WebGL начинается троттлинг: FPS падает
не из-за сцены, а из-за нагрева. Поэтому:
- при `document.hidden` — полная остановка рендера, не просто пауза анимации;
- когда canvas ушёл из вьюпорта (мобильные секции без 3D) — рендер останавливается;
- частицы на мобилке симулируются через кадр всегда, даже на `high`.

## 4. Доступность

3D-сайт по умолчанию недоступен. Чтобы это исправить, нужна дисциплина.

### 4.1 Обязательное

- **Весь контент существует в DOM.** WebGL — только представление. Отключение
  JavaScript оставляет полностью читаемый сайт (SSR-разметка).
- **Порядок фокуса линейный и логичный**, включая карточки проектов и фильтры.
  У каждого интерактивного 3D-объекта есть DOM-двойник — фокусируемая кнопка,
  визуально скрытая, но не `display: none`.
- **Клавиатура:** `Tab` по секциям, стрелки внутри каруселей, `Enter` — вход в
  проект, `Esc` — выход, `Space` — пауза анимаций.
- **Skip-link** первым элементом: «К содержанию» и «К контактам».
- **Видимый фокус** — акцентная обводка 2 px с отступом, не `outline: none`.
- **`prefers-reduced-motion`** — см. [03, раздел 6](./03-motion-scroll-transitions.md).
  Ключевое: контент остаётся видимым, просто без движения.
- **Контраст текста ≥ 4.5:1** в обеих темах, проверяется автоматически. Текст
  поверх 3D всегда имеет подложку (blur + полупрозрачный фон), иначе контраст
  плавает вместе со сценой.
- **`aria-live`-регион** сообщает о смене секции и завершении перехода страницы —
  иначе для скринридера навигация «немая».
- **Кнопка «Отключить эффекты»** в HUD, доступная с клавиатуры на первом же `Tab`.

### 4.2 Что проверяем

- axe-core в Playwright на каждой странице.
- Ручной проход по всему сайту только клавиатурой.
- Проход с VoiceOver/NVDA хотя бы по главной и одному кейсу.
- Проверка с отключённым JS.
- Проверка при 200% зуме и при `font-size: 24px` в настройках браузера.

## 5. Fallback-стратегия

Сайт должен работать в пяти режимах, и каждый — полноценный:

| Режим | Условие | Что видит пользователь |
| --- | --- | --- |
| Полный | WebGL2 + мощное устройство | Всё из плана |
| Облегчённый | слабое устройство | Тот же сайт, меньше эффектов |
| Плоский | нет WebGL / `Save-Data` / выбор пользователя | Статичные постеры вместо 3D, CSS-анимации |
| Без JS | JS отключён | Полный текст, работающие ссылки, читаемая вёрстка |
| Печать | `@media print` | Чистое резюме на 2 страницы |

Отдельный сценарий — **потеря WebGL-контекста** (`webglcontextlost`). Обязательно
слушаем событие, показываем постер и кнопку «Восстановить», а не белый экран.
Это происходит чаще, чем кажется: переключение вкладок на слабой машине, спящий
режим, смена дискретной/встроенной видеокарты на ноутбуке.

## 6. SEO и шеринг

- Весь текст — в серверной разметке. Никакого «контент появляется после
  инициализации сцены».
- `generateStaticParams` для `/work/[id]` — страницы проектов статические.
- `generateMetadata` на каждую страницу: уникальные `title`, `description`,
  `openGraph`.
- **OG-картинки генерируются динамически** через `ImageResponse`: на карточке
  проекта — название, стек, акцентный цвет, отрендеренный заранее кадр 3D-сцены.
  Ссылка, красиво разворачивающаяся в Telegram, — это тоже часть портфолио, а
  Telegram здесь основной канал (он первый в контактах).
- `schema.org`: `Person` на главной, `CreativeWork` на кейсах.
- `sitemap.xml`, `robots.txt`, канонические URL, `hreflang` для ru/en.
- Никаких `#hash`-роутов: секции — якоря, страницы — настоящие URL.

## 7. Аналитика

Минимальная и приватная (Plausible или собственный эндпоинт): просмотры страниц,
глубина скролла по секциям, клики по контактам, выбранный тир качества,
средний FPS по тирам. Последнее особенно полезно — это данные для реальной
оптимизации, а не догадки.

Отдельное событие: «дошёл до контактов». Конверсия портфолио — именно это.
