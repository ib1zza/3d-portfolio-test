# 09 — Дорожная карта

Оценки даны в «вечерах» (2–3 часа сфокусированной работы) — реалистичный формат
для проекта, который делается параллельно с работой. Общая оценка: **48–62 вечера**,
то есть примерно 3–4 месяца при темпе 4 вечера в неделю.

Порядок этапов подобран так, чтобы **после каждого этапа был работающий сайт**,
который не стыдно показать. Это защищает от главного риска — бросить на середине.

---

## Этап 0 — Фундамент (4–5 вечеров)

**Цель:** пустой, но правильно устроенный проект, задеплоенный на домен.

- [ ] `create-next-app` (Next 16, App Router, TS strict), ESLint, Prettier
- [ ] Структура папок из [02](./02-architecture.md), пути-алиасы
- [ ] Перенос данных из старого `portfolio.ts` в новые типы ([06](./06-content-model.md))
- [ ] `/resume` — полностью готовая серверная страница с реальным контентом
- [ ] Базовый layout, шрифты, CSS-переменные тем, HUD-заглушка
- [ ] Деплой на Vercel, домен, аналитика
- [ ] CI: типы, линт, сборка

**Готово, когда:** по домену открывается быстрое текстовое портфолио с резюме и
контактами. Уже можно отправлять в отклик. Дальше всё — улучшение.

---

## Этап 1 — Ассеты (3–4 вечера)

**Цель:** все ассеты оптимизированы и лежат в `public/`.

- [ ] Собрать исходники GLB в `assets-src/`
- [ ] `scripts/optimize-models.ts`, уложиться в бюджеты из [08](./08-asset-pipeline.md)
- [ ] `scripts/sample-points.ts`, облака точек в Uint16
- [ ] HDRI / Lightformer-пресеты
- [ ] MSDF-атлас, подмножества шрифтов
- [ ] `assets:report` в CI

**Риск:** исходные GLB могут оказаться слишком тяжёлыми или неудобными
(много материалов, странные пивоты). Заложить вечер на правку в Blender.

---

## Этап 2 — WebGL-каркас (5–6 вечеров)

**Цель:** один canvas на всё приложение, тиры качества, пустая сцена.

- [ ] `WebGLLayer` + `Canvas` с `ssr: false`, `SceneTunnel`, `View.Port`
- [ ] Lenis, интеграция в цикл R3F, `scroll-store`, `useScrollRange`
- [ ] `quality-store`, `detectTier`, `PerformanceMonitor`, ручной переключатель
- [ ] `CameraRig` с путём по ключевым кадрам
- [ ] Обработка `webglcontextlost`, flat-режим, постер-плейсхолдеры
- [ ] `r3f-perf` и `leva` в dev

**Готово, когда:** по сайту едет камера, FPS-оверлей показывает 60, переключение
тиров работает, на выключенном WebGL сайт не ломается.

---

## Этап 3 — Система частиц (6–8 вечеров)

Самая рискованная и самая ценная часть. Делать целиком в `/playground` как
изолированное демо, интегрировать только когда работает.

- [ ] Ping-pong FBO, симуляция позиций и скоростей
- [ ] Загрузка облаков точек, `DataTexture`, морфинг `uMorph`
- [ ] Curl-noise турбулентность, отталкивание указателем
- [ ] Рендер точек, растяжение по скорости, цвет по скорости
- [ ] Профилирование на мобилке, подбор количества частиц по тирам
- [ ] Фолбэк при отсутствии float render targets

**Готово, когда:** 60 FPS на десктопе при 262k частиц и 45+ на среднем Android
при 65k, морфинг между двумя облаками выглядит как перетекание.

**Если не получится:** запасной вариант — инстансированные меши с морфингом
через `InstancedBufferAttribute` (проще, дешевле, но потолок ~30k элементов).
Визуально слабее, но концепция сохраняется.

## Матрица рисков

| Риск | Вероятность | Влияние | Что делаем |
| --- | --- | --- | --- |
| Частицы не дают нужный FPS на мобилке | высокая | высокое | Тиры качества с самого начала, запасной вариант на инстансах, симуляция через кадр |
| Порталы съедают производительность | средняя | высокое | Максимум 2 живых портала, заморозка остальных, на мобилке — один |
| Переход между роутами мерцает или ломает «назад» | высокая | высокое | Прототип перехода на этапе 5 первым делом, canvas вне снапшота View Transitions, тесты на прерывание |
| `experimental.viewTransition` изменится в Next | средняя | среднее | Изолировать за собственной обёрткой `<PageTransition>`, чтобы замена была локальной |
| iOS Safari убивает WebGL-контекст | средняя | высокое | Потолок тира `high` на iOS, обработка `contextlost`, экономия видеопамяти через KTX2 |
| Проект растягивается и бросается | **высокая** | **критическое** | Этап 0 даёт работающий сайт сразу; каждый этап деплоится; ничего не делается «в стол» |
| Нет материалов по 3D Outlet | высокая | среднее | NDA-приём заложен в дизайн, проект не блокирует релиз |
| Слишком много эффектов, сайт превращается в кашу | средняя | высокое | Правило «максимум один signature-приём на секцию», лишнее уезжает в `/playground` |
| Кириллица в 3D-тексте | средняя | низкое | Экструзия из SVG вместо `Text3D` |

## Definition of Done для любой сцены

Сцена считается готовой, только когда выполнены все пункты:

1. Работает на четырёх тирах качества, включая `flat`.
2. Держит целевой FPS на десктопе и на реальном среднем Android.
3. Читаема и функциональна на мобильном вьюпорте 375×667.
4. Весь её контент присутствует в SSR-разметке.
5. Доступна с клавиатуры, есть DOM-двойники для 3D-взаимодействий.
6. Корректна при `prefers-reduced-motion`.
7. Не оставляет ошибок в консоли и не растит heap при 10 монтированиях.
8. Тексты написаны на ru и en.
9. Есть постер для flat-режима.

## Порядок, если времени мало

Если нужно выкатить быстро (например, ищется работа прямо сейчас), минимальная
версия, которая всё равно производит впечатление:

**Этап 0 → Этап 1 → Этап 2 → Этап 3 → Hero + Витрина + Контакты → Этап 7.**

Это примерно 25 вечеров и даёт: живое ядро частиц, морфинг между проектами,
порталы, контакты и полностью доступный сайт. Коридор опыта, сосуд со скиллами,
миры проектов и playground добавляются потом, не ломая ничего.
