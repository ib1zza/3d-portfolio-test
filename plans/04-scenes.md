## 00 — Ignition (прелоадер)

**Смысл.** Первое доказательство внимания к деталям: даже загрузка — часть продукта.

**Что видно.** Чёрное (или бумажное, по теме) поле. По центру тонкая
горизонтальная линия — «сопло». Из неё вытекает поток частиц, который постепенно
собирается в плотное ядро. Слева внизу моноширинный лог реального прогресса:

```
loading  environment.ktx2      312 KB   ✓
loading  points/hero.bin       180 KB   ✓
loading  cartoon-teeth-set.glb 244 KB   ▓▓▓▓▓░░░ 62%
```

**3D.** Ядро частиц — та же система, что будет жить весь сайт; она не
пересоздаётся, а просто продолжает работать. Прелоадер не «сменяется» главной, он
в неё перетекает: ядро остаётся на экране, вокруг него проявляется остальное.

**Взаимодействие.** Кнопка `Skip` появляется через 1.2 с. Клик — мгновенный
переход в hero с частицами в текущем состоянии.

**Мобилка.** Лог сворачивается в одну строку и процент.

**Деградация.** `flat`: обычный тонкий progress bar сверху, 200 мс, и всё.

**Ограничение.** Жёсткий потолок 2.5 с. По истечении — показываем сайт независимо
от прогресса, недогруженное дозагружаем в фоне. Прелоадер, который держит дольше,
работает против портфолио.

## 01 — Hero: «Материя»

**Смысл.** Кто это и что он делает. Плюс мгновенная демонстрация уровня.

**Что видно.** Слева крупно, дисплейным шрифтом:

```
Михаил
Пшеничный
```

Ниже моноширинным: `Frontend developer · Nuxt / Vue / React / TypeScript · Санкт-Петербург`.

Справа и частично за текстом — живое ядро из ~250k частиц: медленно вращающееся,
дышащее облако, которое всё время находится на грани формы. Периодически (раз в
8–10 с) оно на секунду «схватывается» в узнаваемый силуэт (зуб, футболка, принтер)
и снова рассыпается — превью того, что будет дальше по скроллу.

**3D.**
- GPGPU-система частиц (см. 05, раздел 1). В hero целевая позиция — сфера с
  шумовой деформацией; периодические «схватывания» — кратковременное подмешивание
  одного из облаков проектов с весом 0.85 и быстрый возврат.
- Цвет частицы зависит от её скорости: медленные — цвет `--ink-muted`, быстрые —
  акцент. Даёт объём без освещения.
- Фон — raymarching-квад с мягким жидким градиентом.

**Взаимодействие.**
- Указатель отталкивает частицы (сила по обратному квадрату расстояния, радиус ~1.5 юнита).
- Клик и удержание — частицы стягиваются к точке, при отпускании разлетаются волной.
- Скролл растягивает частицы по направлению движения (velocity-driven stretching).

**Мобилка.** Текст сверху, ядро снизу, 45vh. Отталкивание — по касанию. Частиц
60k. Ядро смещено так, чтобы не попадать под большой палец.

**Деградация.** `medium`: 80k частиц, без raymarching-фона (заменяется на CSS-градиент).
`flat`: статичное изображение ядра (WebP, отрендеренный заранее) + CSS-параллакс.

## 02 — Манифест

**Смысл.** Профессиональное позиционирование, `profile.summary` человеческим языком.

**Что видно.** Крупный текст на 3–4 строки, набранный в две колонки. Ключевые
слова («Nuxt», «React», «TypeScript», «производительность») — не DOM-текст, а
3D-меши, стоящие ровно в строке. Они слегка выступают из плоскости, отбрасывают
мягкую тень на «бумагу» и медленно поворачиваются от параллакса.

Это и есть главный трюк секции: **читатель не сразу понимает, где кончается
вёрстка и начинается WebGL**.

**3D.**
- 3D-текст через `drei/Text3D` (для латиницы) или экструдированные SDF-формы,
  собранные заранее (кириллица в `Text3D` требует подготовленного шрифта — см. 08).
- Материал: `MeshStandardMaterial` с `clearcoat`, акцентный цвет, `Environment` из HDRI.
- Позиционирование — через `drei/View`, привязанный к inline-span в тексте, чтобы
  при перевёрстке (мобилка, смена языка) слова оставались на своих местах.

**Взаимодействие.** Наведение на 3D-слово — оно всплывает к камере и подсвечивается,
рядом всплывает моноширинная подпись с годами опыта в этой технологии.

**Мобилка.** 3D-слова остаются, но только два самых важных (иначе перегруз);
остальные — обычный текст с акцентным подчёркиванием.

**Деградация.** `medium`: 3D-слова становятся плоскими планами с текстурой и
нормалмапом. `flat`: обычный текст с градиентной заливкой.

## 03 — Фокус: пять инструментов

**Смысл.** `profile.focus` / `focusAreas` — пять направлений работы.

**Что видно.** Пять абстрактных объектов на круговой орбите, повёрнутой к зрителю
почти ребром. Каждый — метафора направления:

| Направление | Объект |
| --- | --- |
| Коммерческие сайты на Nuxt/Vue | Слоистая пластина, «стопка страниц» |
| React + TypeScript приложения | Кристаллический модуль с гранями-компонентами |
| UI-киты | Набор одинаковых элементов, собирающихся в решётку |
| Анимация интерфейсов | Лента, изгибающаяся по синусоиде |
| Производительность | Кольцо, которое сжимается и ускоряется |

Активный объект — в центре, крупный; остальные уменьшены и расфокусированы (DOF).
Рядом — текст направления и связанные проекты (кликабельно).

**3D.** Инстансированная геометрия там, где возможно. Орбита управляется прогрессом
скролла: секция занимает ~1.5 экрана, за это время орбита проворачивается на 5 позиций.

**Взаимодействие.** Свайп/драг по орбите, стрелки клавиатурой, клик по объекту.
Каждый объект деформируется при наведении собственным вершинным шейдером.

**Мобилка.** Орбита превращается в вертикальную «карусель-стопку»: активный объект
крупно, соседние — срезами сверху и снизу. Свайп вертикальный, snap.

**Деградация.** `medium`: без DOF, орбита из простых геометрий.
`flat`: сетка из пяти карточек с SVG-иконками.

## 04 — Коридор опыта

**Смысл.** Опыт работы: GROKHOTOV STUDIO (Nuxt, с сентября 2025) и ApexNovaTech
(React + TS, январь–август 2025). Это самая важная секция для нанимающего.

**Что видно.** Камера летит вперёд по «коридору времени». Годы отложены по оси Z:
чем дальше — тем раньше. По стенам коридора проплывают панели с обязанностями и
достижениями, оформленные как технические таблички. Каждая компания — «станция»:
коридор расширяется в зал, камера притормаживает, панель с названием компании
разворачивается фронтально, вокруг собираются объекты её проектов.

**3D.**
- Коридор — инстансированные рёбра/панели, порядка 200 инстансов, один draw call.
- Туман по глубине (`fogExp2`) в цвет фона: скрывает дальнюю границу и даёт
  бесплатную глубину.
- Свет движется вместе с камерой, панели проявляются из темноты.
- На «станциях» — маленькие 3D-объекты проектов, к которым эта работа относится
  (зуб для Simplex, футболка для Silkworm — оба сделаны в GROKHOTOV STUDIO).

**Взаимодействие.** Скролл = движение вперёд. Клик по панели проекта — раскрытие
портала и переход в кейс. Клик по табличке компании — раскрывается развёрнутый
список обязанностей (DOM-панель поверх, с blur-подложкой).

**Мобилка.** Коридор становится вертикальной шахтой: камера едет вниз, панели —
слева и справа, текст под каждой панелью в DOM. FOV шире.

**Деградация.** `medium`: коридор из 40 панелей, без тумана и динамического света.
`flat`: классический вертикальный таймлайн с линией и точками.

## 05 — Сосуд со скиллами

**Смысл.** 20 технологий из резюме — но не тегами, а физическими объектами.
Показывает, что автор умеет в физику и в тактильность интерфейса.

**Что видно.** Прозрачный сосуд (стекло с преломлением). Внутри — 20 «таблеток»
с названиями технологий, лежащих кучей. Они реагируют на всё: на наклон телефона,
на бросок мышью, на скролл (при быстром скролле встряхиваются).

**3D.**
- `@react-three/rapier`: 20 динамических тел (скруглённые цилиндры), сосуд —
  статичный коллайдер из нескольких плоскостей (не trimesh — дорого).
- Надписи на таблетках — MSDF-текст, запечённый в атлас (одна текстура на все 20),
  таблетки инстансированы: один draw call на все тела.
- Стекло — `MeshTransmissionMaterial` с `samples: 6`, `resolution: 512` на `ultra`,
  `samples: 2`, `resolution: 256` на `high`, фейковое стекло ниже.
- `Physics` монтируется только когда секция во вьюпорте, и ставится на паузу при уходе.

**Взаимодействие.**
- Десктоп: захват тела курсором (`useSpringJoint` или kinematic-хват), бросок с инерцией.
- Мобилка: **гироскоп**. Запрашиваем `DeviceOrientationEvent.requestPermission()`
  по явному нажатию кнопки «Наклоняй» (iOS требует жест пользователя). Вектор
  гравитации в мире Rapier поворачивается по ориентации устройства.
- Кнопка «Встряхнуть» — импульс всем телам, работает везде.
- Клик по таблетке — фильтрует список проектов ниже по этой технологии и
  подсвечивает их в витрине.

**Клавиатура.** Секция дублируется скрытым, но фокусируемым списком технологий —
чтобы фильтрация работала без физики.

**Мобилка.** Сосуд занимает 55vh, тел 14 вместо 20 (самые важные), стекло фейковое.

**Деградация.** `medium`: физика есть, стекло фейковое, тел 12.
`flat`: обычные чипы-теги с фильтрацией — функционально то же самое.

## 06 — Витрина: порталы проектов

**Смысл.** Главный раздел. Пять проектов, каждый — отдельный мир.

**Что видно.** Горизонтальная лента из «окон». Каждое окно — не картинка, а
настоящее отверстие в другую сцену: за стеклом свой фон, свой свет, свой объект,
свой акцентный цвет. Внутри окна объект живёт: медленно вращается, реагирует на
приближение курсора, частицы перетекают между окнами.

Под каждым окном — моноширинная сводка: год, статус, роль, стек, тип проекта.

**3D.**
- `MeshPortalMaterial` из drei на плоскости с закруглёнными углами. Каждый портал
  рендерит собственную мини-сцену в свой render target.
- Экономия: одновременно рендерятся только 2–3 видимых портала, остальные
  замораживаются (`worldUnits`/`frames={1}` или ручное управление `renderPriority`).
- Между окнами тянутся нити частиц — визуальная связь «одна материя».

**Взаимодействие.**
- Горизонтальный скролл/свайп, snap по окнам.
- Наведение — портал слегка «выдувается» к зрителю, объект внутри приближается.
- Клик — портал раскрывается на весь экран и переводит на `/work/[id]`
  (сценарий из [03, раздел 3.2](./03-motion-scroll-transitions.md)).
- Фильтры сверху: `коммерческие / текущие / пет-проекты`, `по стеку`. Фильтрация
  анимирована: отфильтрованные окна не исчезают, а гаснут и уезжают вглубь.

**Мобилка.** Вертикальный стек порталов, каждый 60vh, snap-scroll. Одновременно
рендерится один активный портал, соседние — статичные предзапечённые кадры.

**Деградация.** `high`: порталы есть, но мини-сцены упрощены.
`medium`: вместо порталов — плоскости с видео/изображением и шейдерным hover-переходом.
`flat`: сетка карточек со скриншотами.

## 07 — Мир проекта (`/work/[id]`)

Один шаблон, пять наполнений. Структура страницы:

```
[ герой кейса: имя проекта, год, роль, живой 3D-объект ]
[ витрина: живой сайт / скриншоты в 3D-раме ]
[ задача → решение → результат (caseStudy) ]
[ обязанности + фичи, два столбца ]
[ метрики крупными цифрами ]
[ стек чипами ]
[ ссылки: Live / GitHub ]
[ следующий проект: портал, ведущий дальше ]
```

Общее для всех: при входе акцентный цвет проекта заливает всю сцену — свет,
bloom, подчёркивания, цвет частиц. Ощущение «я в другом мире», хотя технически
это та же сцена.

### 07.1 Simplex Clinic

Модель `cartoon-teeth-set.glb`, логотип `simplex.glb` парит над ней и медленно
вращается. Акцент — мятный, свет холодный, «клинический». Сцена стерильно чистая,
много белого пространства, мягкие тени.

Фишка секции: **срез**. По скроллу через модель проходит плоскость сечения
(clipping plane) со светящейся линией среза — визуальная рифма к «разбираю
интерфейс на слои». В момент среза сбоку выезжают слои UI-кита проекта: кнопки,
инпуты, карточки — как реальные компоненты, которые автор делал.

Витрина: живой `simplexclinic.ru` в iframe внутри 3D-рамки ноутбука, с
отражением на «столе» под ним. iframe — через `drei/Html` с `transform`, грузится
лениво по клику на «Открыть живой сайт» (иначе третий-сторонний сайт съест
производительность и приватность).

### 07.2 Silkworm

Модель `t-shirt.glb` + `cap.glb`, логотип `silkworm.glb`. Акцент — фуксия.

Фишка секции: **ткань**. Футболка колышется — вершинный шейдер с шумом, реагирует
на движение курсора как на ветер. Плюс переключение «материала»: клик по свотчам
меняет шейдер ткани (шёлк с анизотропным бликом, хлопок с матовым шумом, деним) —
прямая отсылка к ecommerce-конфигуратору.

Витрина: карусель скриншотов каталога в 3D, страницы перелистываются с шейдерным
переходом-волной.

### 07.3 3D Outlet (приватный, NDA)

Модель `printer-scanner.glb`. Акцент — янтарный.

Фишка секции — **обыгранная приватность**. Принтер стоит в сцене, но всё, что
относится к интерфейсу заказчика, показано «зашифрованным»: планы с UI
пикселизируются, глитчатся и разбираются на блоки при попытке приблизиться.
Поверх — моноширинная плашка `CLASSIFIED · NDA`, и рядом человеческий текст:
что именно делал автор и почему не может показать.

Дополнительно принтер «печатает» маленький объект в реальном времени: слой за
слоем, по прогрессу скролла (clipping plane снизу вверх + светящаяся линия
экструзии). Это самый прямой визуальный мостик к главной метафоре сайта.

Ограничение по контенту: показывать только то, что согласовано. Пока нет
согласования — только 3D и текст, без единого скриншота.

### 07.4 Realtime Chat

GLB нет, и он не нужен: чат-пузыри делаются **процедурно** через метаболы
(marching cubes из drei или SDF-raymarching). Пузыри слипаются и разлипаются —
буквально «живое сообщение». Акцент — индиго.

Фишка секции: **живая переписка**. Пузыри всплывают снизу вверх, в них —
настоящие сообщения (MSDF-текст), которые складываются в рассказ о проекте:
«Firebase realtime», «Google auth», «файлы», «темы», «i18n». Это одновременно
контент и демо технологии.

### 07.5 Kanban

Тоже процедурно: три колонки, карточки — инстансированные плоскости с физикой.
Акцент — индиго/янтарь.

Фишка секции: карточки можно **реально перетаскивать между колонками в 3D**, и
они падают с физикой. При переносе карточки в «Done» она рассыпается на частицы,
которые улетают в общий поток. Список карточек — реальные факты о проекте (FSD,
Redux Toolkit, Storybook, Jest, Firebase RTDB).

## 08 — Playground (`/playground`)

**Смысл.** Раздел для технического читателя: доказательство, что шейдеры на
сайте — не купленный шаблон.

**Что видно.** Сетка из 6–9 мини-демо, каждое в своём `drei/View`. Под каждым —
краткое описание техники и ползунки параметров (leva или собственные, лёгкие).
Клик — демо разворачивается на весь экран, появляется вкладка с исходником
фрагментного шейдера с подсветкой синтаксиса и кнопкой «копировать».

Кандидаты в демо: curl-noise частицы, raymarched SDF, симуляция жидкости на
текстуре, дисплейсмент-переход изображений, инстансированная волна, эффект
хроматической линзы, MSDF-текст с деформацией, метаболы.

**Взаимодействие.** Ползунки, drag, полноэкранный режим, deep-link на конкретное
демо (`/playground?demo=curl-noise`) — чтобы можно было скинуть ссылку в отклике.

**Мобилка.** По одному демо на экран, ползунки — крупные, снизу.

**Деградация.** Раздел целиком скрыт на `flat` (там ему нечего показать),
вместо него ссылка на Storybook и GitHub.

## 09 — Контакты: «Подпись»

**Смысл.** Закрыть сделку. Контакты должны быть очевидны и кликабельны.

**Что видно.** Все частицы сайта стягиваются в одну точку и выписывают подпись —
имя автора, нарисованное как непрерывная линия (частицы едут по кривой). Под
подписью — четыре крупные ссылки: Telegram, VK, GitHub, Email.

**3D.** Кривая подписи — заранее подготовленный `SVG path` → сэмплированные точки
→ целевое облако для GPGPU-системы. Частицы едут по кривой с фазовым сдвигом,
создавая эффект «пишущей руки», цикл 4 с.

**Взаимодействие.** Наведение на контакт — частицы стягиваются к нему и образуют
иконку сервиса. Клик по email копирует адрес в буфер с тактильным
подтверждением. Кнопка «Скачать резюме (PDF)» и ссылка на `/resume`.

**Мобилка.** Подпись мельче, контакты — крупные тап-таргеты минимум 48 px,
в один столбец.

**Деградация.** `flat`: SVG-подпись с CSS `stroke-dashoffset` анимацией — визуально
почти то же самое, стоит копейки.

## 10 — `/resume`

Никакого WebGL. Серверный рендер, один экран прокрутки, семантическая разметка,
`@media print` для чистого PDF, микроразметка `schema.org/Person` и
`schema.org/JobPosting`-совместимые блоки опыта. Загружается меньше чем за
секунду на 3G. Ссылка на неё присутствует в HUD на всех страницах.

Далее: [05-shaders-and-effects.md](./05-shaders-and-effects.md).
